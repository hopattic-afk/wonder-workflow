# Data model

The audit stores version 1 JSON at `mccann-ai-operations-audit:v1` in localStorage. Call notes, pricing, edits and documents are not uploaded. The enabled bridge stores assessments and supplies booking packets through an authenticated inbox. Actual readback preserved one packet, the original seven scored answers plus context (31 entries), score 21/max21, CRM phone fallback, rescheduled time and subsequent cancellation. Duplicate replay reused the packet. Browser profiles/devices have separate stores; export backups. See [activation record](docs/ACTIVATION-RECORD-2026-09-05.md) for live/API versus browser test limits.

- `Store`: version, sessions, local settings, last full export, last successful save, optional `dismissedMeetings` identifiers preventing deleted imports from reappearing. Old backups remain valid. Explicit restoration of an audit allows updates again.
- `Session`: stable ID, timestamps, dashboard status, archive/demo flags, client, worksheet, ordered workflow steps, software, calculator, editable recommendation and proposal, call notes, optional timer.
- Optional `Session.intake`: normalized booking packet, original assessment answers and retained submission history, sourced research notes, last imported field values, and proposed changes conflicting with manual edits. Existing version 1 backups without this property remain valid.
- `Client`: business/contact details, currency, audit date, optional assessment score (0–21), tier and priority.
- `Worksheet`: objective, workflow context, baseline, AI classifications, human review, data rights, risk controls, ten optional 1–5 fit ratings, internal decision and rationale.
- `Calculator`: working weeks, labor/rework/recurring rows, optional avoided hire, manual proposed price and optional discount. Financial totals are derived, never persisted as authoritative values.
- `Recommendation` / `Proposal`: editable generated text, generation timestamp and source fingerprint. Fingerprints detect changed source assumptions; these are noncryptographic change markers. Proposal fingerprints also include the recommendation. Regenerating a document is a replacement operation controlled by the UI.
- `Settings`: company and consultant details, USD/CAD default, working weeks, optional stabilization period, gold accent, optional local raster logo, document footer.

The default accent is bronze gold (`#C29A60`). Loading a saved workspace or importing a backup updates only the original gold preset (`#D4AF37`); other custom colors and all audit inputs are preserved. Assessment scores are whole numbers from 0–21. Existing scores retain their recorded value rather than being rescaled.

Missing numeric values are `null`, never empty strings or invented numbers. Strings are plain text rendered by React; document generators do not copy client notes, call notes, recommendation rationale, or internal pricing notes into client-facing documents. Rationale inclusion requires a separate explicit UI toggle.

Document generation follows the selected recommendation decision. Only an explicit `Proceed with AI pilot` decision generates a suggested AI implementation checklist. Discovery, cleanup and software consolidation get their own bounded draft scope. A negative, referral or unset decision has no implementation deliverables; marketing classification overrides an otherwise positive decision. Generators never mutate existing session notes or edited documents. Generating a proposal from a stale recommendation preserves edits and inserts a visible draft notice; `proposalUsesStaleRecommendation` also supports the internal UI warning. Client documents include relevant entered risk areas, data sensitivity, data rights, review and accuracy controls, without internal fit scores or rationale. Empty financial categories remain unknown in client-facing impact text even though they contribute zero in calculation bookkeeping.

`validation.ts` uses strict Zod objects to reject unknown fields, unsupported versions, invalid types, non-finite and out-of-range numbers, invalid dates/emails, malformed logos, and duplicate IDs. Each session has unique row IDs; copied sessions may reuse row IDs because their session IDs isolate their records. Limits: 500 sessions, 200 rows per collection, 32,000 characters per general text field, 2,000,000 characters per local PNG/JPEG/WebP logo, 25 MB per backup. SVG and remote logo URLs are rejected.

`parseImport` is pure: it validates a full replacement store without modifying storage. `saveStore` validates and serializes before its single write. Both corrupt existing storage and unavailable/quota-limited storage throw to the UI; only an absent key returns `null`. This prevents a read failure from being mistaken for a new empty store. Future format versions require an explicit migration, not coercion.

`parseIntakePacket` validates prepared-meeting JSON independently of backups. `applyIntakePacket` is a pure local merge, restricted to the verified McCann location/calendar and a field allowlist. It keys audits by appointment, verifies contact identity, rejects ambiguous equal-time updates, ignores stale deliveries, and preserves manually edited/cleared fields. Empty research updates retain previous sourced facts. A score requires maximum21; legacy18 results remain original-answer context without rescaling. Booking time retains an offset and IANA timezone. Original answers and research are metadata, not inferred pricing, savings, Pilot-Fit scores, consent, or document content. The server bridge uses this same validated packet contract.
